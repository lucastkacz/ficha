# A deck travels as a .ficha file, with its emoji and description

On 2026-11-27, while Ficha's three decks were being built (#458, PR #547), Lucas asked for a short description of each, such as which years Arte argentino spans, and then that it live inside the deck's file, with its emoji, so that anyone who brings a deck in gets both, not only Ficha's decks (#554). After ADR 0041 no file comes in or goes out but Ficha's own decks, unseen, so a deck could only travel if a file came back. In the debate "Emoji y descripción del mazo", three rounds the same morning, he chose to open a deck someone sends him, a description on any deck, and a file of Ficha's own. In his notes he wrote that the friend he passes a deck to isn't technical and only opens it, and he asked to both share it and save it. He approved the decision the same day, in the artifact "Emoji y descripción: decisión", with no notes. It changes ADR 0041 in part, under which no zip came in or went out; ADR 0014 in part, whose zips were Ficha's own deck files alone; and ADR 0035 and ADR 0040 in part, whose decks' files were zips with no emoji or description, the only files that came in.

- **A deck has a description.** It is one or two lines, at most 160 characters (provisional), on any deck, Ficha's or the user's, saying what the deck holds. It shows where a deck is chosen, on the Welcome page's tiles and in the Cards window's Ficha's Decks, and above a deck's cards once it's added. The user writes or changes it the way they give a deck its emoji: Description… among the deck's actions, and `ficha deck description` (provisional). It lives in the deck's row and syncs as a field of the deck's iCloud record (provisional). An update of the app never changes it.
- **A deck's file is a `.ficha`.** A zip, through ZIPFoundation (ADR 0014), holding the cards' text file as the import reads it today, their images and sounds, and `deck.json`, with the deck's emoji and description (provisional). It never holds the user's progress, as today's export doesn't. Its own Uniform Type Identifier conforms to zip, and the app declares it and opens it, so a double-click in Finder opens Ficha.
- **A deck someone sends comes in.** A double-click on a `.ficha`, or Open Deck… in the Cards window, asks How fast? (ADR 0034) and brings the deck in, as Add Deck… brings in one of Ficha's. A deck that comes in new takes the file's emoji and description. A deck the user already has keeps its own and takes only the cards it lacks (provisional). Only `.ficha` files come in; Anki's packages, text files and other zips stay out, as ADR 0041 has them (provisional). The Welcome page stays as ADR 0041 has it: Ficha's decks, or a deck of one's own.
- **Any deck goes out.** Share Deck…, among a deck's actions, opens macOS's Share menu with the deck's `.ficha`. The menu ends with Save to File…, which saves the file through a save panel (provisional: one button, not two, since the app has no main menu to hold a File › Export). Any deck the user has added can go out this way, Ficha's too (provisional). `ficha deck export` writes the same file, for agents.
- **Ficha's decks are `.ficha` files.** Their emoji and description come from their `deck.json`, in Spanish for now (ADR 0040), and the emoji written in the code for each goes.

## Considered options

- The description and emoji for Ficha's decks alone, written in the code, with nothing coming in: Lucas wants any deck to have them, and to pass his decks to friends.
- A `.zip`: double-clicked, it unzips into a folder. A type of Ficha's own opens Ficha, as Anki's packages open Anki.
- The file made only by a command: the friend who gets it, and most people who'd share one, never type one. Made only in the app: an agent that makes a deck for the user couldn't hand it over. So both.
- Share and Save as two buttons: one button whose Share menu ends with Save to File… (provisional).
- A deck someone sends also dropped on the Welcome page: the Welcome page keeps its two ways in.
- An icon, or the first card's picture, in place of the emoji: the emoji already marks the deck and already syncs.
- The emoji and description in header lines of the cards' text file: `deck.json` beside it leaves the text file as the import reads it today (provisional).

## Consequences

- #554 becomes the Feature for the file, in Mac › Cards › Import: the engine reads and writes a `.ficha`, Ficha's decks become `.ficha` files with their descriptions, and Open Deck… and a double-click bring one in. A Feature in Core › Data keeps and syncs a deck's description; one in Mac › Cards shows and changes it and adds Share Deck…; one in Mac › CLI adds `ficha deck description` and `ficha deck export`. #467's Welcome page shows each deck's description.
- #542 changes in part. The Import and Export sheets, Anki's readers and zstd still go. The engine's export stays, writing a deck's `.ficha`, and its import reads any `.ficha`, not only Ficha's.
- iCloud's Production schema gets the description field before the next `make upload` ("A new record type or field in iCloud" in `docs/development.md`).
- `PLIEGO.md` says it: in What it is; in Mac › Cards › Import's line; in Hands-free's line on the CLI; in the plano, where the app opens `.ficha` files, FichaData imports and exports them, and Ficha's decks are `.ficha` files; and in Open, where the paywall's line names Share Deck…. `GLOSSARY.md` gains a deck's file and its description now; Import and Export change with the nodes that build them, as ADR 0041 has its words change.
- Whether Share Deck… stays once the free days are over is #459's to decide (ADR 0029, ADR 0041).
- Later: a page where people share decks (ADR 0035), what a friend without Ficha sees, and an icon or picture in place of the emoji.
- Standard practice: a document type of the app's own, declared as a Uniform Type Identifier and opened with a double-click; macOS's Share menu, through AppKit's `NSSharingServicePicker`. Our own: `deck.json` beside the cards' text file, Save to File… at the Share menu's end, and a description of at most 160 characters.
