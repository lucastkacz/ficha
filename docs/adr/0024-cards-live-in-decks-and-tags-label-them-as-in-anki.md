# Cards live in decks, and tags only label them, as in Anki

ADR 0011 made tags Ficha's subjects instead of decks, and ADRs 0020 to 0022 built on them: tags inside tags, selective sync and pinned tags. On 2026-10-29 Lucas imported an Anki package, Great Works of Art, into the real Ficha's build 144. In Anki it's a deck with two decks inside it, Artists and Titles, and its notes carry Anki's tags, such as Renaissance and Sculpture. The Import sheet listed them all as tags: `Great Works of Art::Artists` beside `Renaissance`. Ficha's tags did two jobs, where a card lives and a label that crosses subjects, and both took the same switches. So in the grilling of 2026-10-30 Lucas decided that Ficha has both, as Anki does, and copies Anki wherever it can, so that switching from Anki is seamless. Each card lives in exactly one deck. Decks sit inside decks by their names, `Great Works of Art::Artists`, and Default holds the cards with no other deck. Set aside, priority and selective sync move to decks, and tags become labels with no switches. Tags keep their tree, color, emoji, pins and All Tags.

## Considered options

- Tags alone, with the import telling an Anki deck from Anki's tags: less to build, but once in, Anki's tags would sit beside the user's subjects in All Tags, with the same switches.
- A card in several decks, Lucas's first idea for subjects that overlap: decks would turn back into tags, a card in a deck set aside and in another not would need a rule, Anki couldn't read the export, and every deck would count the card. Overlap is what tags are for.
- Priority on tags as well, for an exam that crosses decks: Anki does that with filtered decks, which Ficha lacks. It can still come later, since CloudKit takes new fields after Production.
- The sidebar listing the decks the user pins, with All Decks… for the rest, as ADR 0022 does for tags: the order would be the user's own, but it needs one more page, and Anki lists every deck.
- Deleting a deck moving its cards to Default: safer, but the cards would then have to be found among the rest there and deleted by hand.
- Ficha guessing each card's deck from its tags, such as its first one: quick, but wrong for cards the user made. Importing the Anki packages again would lose the progress made in Ficha since.

## Consequences

- It changes ADR 0011: set aside and priority belong to decks, and set aside holds for a deck's cards and those of every deck inside it. ADR 0011's reasons for one stream stand: a deck has no settings of its own, the ladder and the new cards a day are the same for every deck, and nothing reviews one deck alone. A Review now of one deck could come later, since it needs no change to what syncs.
- It changes ADR 0020: selective sync chooses decks. A card syncs when its deck, or a deck its deck sits inside, is chosen. Default can be chosen. A new deck inside a chosen one syncs, and any other waits until the user ticks it. Moving a card into a deck that isn't chosen stops it syncing, as unticking does, and deletes no card. Tags always sync, as everything that isn't a card does. The Sync tab lists the decks as a tree, each with what its images and sounds weigh.
- It changes ADR 0021: what it says of tags inside tags holds for decks inside decks too, such as renaming, merging, dragging, and a parent's color and emoji for a deck that has none. Tags keep their tree without switches. An Anki package's deck comes in as a deck, by its whole name, in place of a tag. The cards in Anki's Default go to Ficha's, a deck whose name exists takes the cards, and a note's tags come in as tags.
- It changes ADR 0022's sidebar, which gets a Decks section. It lists every deck as a tree, alphabetical as in Anki, with parents that open and close and how many cards each deck has due, its decks inside counted. A deck set aside is grayed. A deck's menu holds Set Aside, Prioritize, Rename…, Color, Emoji… and Delete…. The Tags section keeps the pinned tags and All Tags…, which loses its Priority and Set Aside. The menu bar's Prioritize submenu lists the decks, with a submenu for each parent. In the sidebar, a card dropped onto a deck moves to it. A deck dropped onto a deck goes inside it, and one dropped onto the Decks title goes to the top. Tags are still dragged in All Tags.
- Choosing a deck shows its tags above the card list, with how many of its cards carry each, those of its decks inside included, most cards first. Clicking one lists only the cards that carry it, and clicking it again lists them all.
- The review panel shows a card's deck first, by its whole name and with its color and emoji, then its tags.
- Deleting a deck deletes it, the decks inside it and all their cards, on every device that syncs them, as Anki does. It asks first, saying how many cards and decks it deletes.
- A new card starts in the deck chosen in the sidebar, or else the last deck the user put a card in, as Anki's Add window does. Approving a capture chooses its deck. The CLI and `/refine` name each card's deck, and a card they don't put in one goes to Default. Change Deck… moves cards between decks.
- The text file gets a Deck column, which Export writes with Anki's `#deck column` header, so Anki reads it too. Import reads it, from Ficha's files or Anki's, and for a file without one, the Import sheet chooses a deck, Default when the user doesn't. The Import sheet lists an import's decks and tags apart, and the user can rename each.
- Lucas's cards move in a conversion he approves. The update, with its copy before an update, puts every card in Default and leaves its tags as they are. The same day, in a session Lucas starts, Claude lists his tags through the CLI, with how many cards each has. Claude proposes which become decks, and Lucas approves the list. Then a CLI command moves every card with each of those tags, or a tag inside it, into a deck of the same name. The tag comes off the card, and its color, emoji, set aside, priority and choice to sync go to the deck. A card with two tags that become decks goes to the first and keeps the other as a tag, and the conversion lists those cards before it runs. Until it runs, Lucas's set-aside tags don't hold. It's a CLI command alone, since nobody else has cards from before decks.
- The `ficha` CLI does for decks what it does for tags (ADR 0022), and its tag commands lose set aside, priority and the choice to sync. The content guide puts each card in the deck of its subject, and uses tags for what crosses subjects.
- Card types don't change.
- It's built before #318. Once a CloudKit schema is in Production, Apple allows only additions to it: no record type or field can be deleted or renamed (Apple's "Deploying an iCloud Container's Schema"). Until #318 deploys it, nothing is in Production, so the fields tags no longer use can still leave the Development schema.
- The iPhone does the same (ADR 0019).
- Standard practice: Anki's decks, with one deck per card, a tree of names joined by `::`, a parent that takes in the decks inside it, Default, Change Deck, a deck list with its due counts, and deleting a deck with its cards. Also Anki's tags as labels, and its `#deck column` header. Our own: no settings per deck and no reviewing one deck alone, set aside and priority on decks, selective sync by decks, a deck's tags above its cards, the deck in the review panel, and the conversion Lucas approves.
