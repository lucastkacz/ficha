# FSRS's arithmetic comes from fsrs-rs, the Rust library Anki ships

ADR 0025 has Ficha schedule with FSRS, as Anki does, and spec #404 first planned FSRS-6 as our own Swift code. On 2026-11-01 Lucas decided not to reinvent the wheel: FSRS's arithmetic comes from fsrs-rs, the FSRS authors' Rust library, at the version Anki ships, 6.6.2. That arithmetic is a card's stability and difficulty after each rating, the interval for a desired retention, a stability and difficulty started from an SM-2 interval and ease, retrievability, the default parameters and, once Optimize comes as an issue of its own, the fitting of the parameters to the user's reviews, fsrs-rs's `compute_parameters`. Rust runs on phones as on the desktop: AnkiDroid runs Anki's Rust core through Anki-Android-Backend, and Firefox for iOS ships Mozilla's Rust components as a Swift package. Anki's rules around FSRS stay ours, in Swift, since Anki keeps them in its own code and not in fsrs-rs: the learning and relearning steps, rounding an interval to whole days within its bounds, keeping hard, good and easy a day apart, and the fuzz. Ficha reaches fsrs-rs through a small Rust crate of its own, which exports the few functions Ficha calls as a C interface, built into an XCFramework that FichaKit links for the Mac and the iPhone.

## Considered options

- FSRS-6 written in Swift, as #404 first planned: its scheduling formulas are short, but Optimize isn't, since fsrs-rs computes its gradients by hand in thousands of lines that a port would have to get right, and every FSRS release, such as FSRS-7, which models hours, would be another port.
- swift-fsrs, the FSRS authors' Swift port (MIT): it has no optimizer, and it steps a card object forward, while Ficha replays a log that two devices' entries join.
- fsrs-rs-c, the FSRS authors' C binding: it's built on fsrs 5.2.0, not the 6.6.2 Anki ships, as a dynamic library, which an iOS app can ship only wrapped in a framework of its own, and it hands out heap pointers to free.
- UniFFI, Mozilla's bindings generator, in place of a C interface: it generates the Swift side, which would have to pass Ficha's lint and Swift 6's checks with warnings as errors, a cost worth paying for a large surface but not for a handful of functions on numbers.

## Consequences

- fsrs-rs is Ficha's fifth dependency, pinned exactly, `=6.6.2`, where Anki's manifest asks for 6.6.2 or a compatible release and its lock holds 6.6.2, with `Cargo.lock` committed and every build run with `--locked`; this is the ADR that `CODING_STANDARDS.md` asks for, and its Dependencies rule, which names only `Package.swift` and `Package.resolved`, grows to cover Cargo's pin and lock. It brings ndarray, rayon, rand, serde, itertools, snafu, strum, log and priority-queue; burn, the machine-learning framework, is only a development dependency of fsrs-rs, so Ficha doesn't build it.
- fsrs-rs's BSD-3-Clause notice, and the notices of the crates it brings, go with the app, as every dependency's do for the App Store release (ADR 0015, #160).
- The crate's manifest, its lock and the Rust toolchain's pin join the merge gate's paths, so upgrading fsrs-rs, which can change intervals, is a `risk:high` PR that Lucas merges, as Anki moves its own pin deliberately. Dependabot watches Cargo monthly, as it watches the Swift packages.
- The build gains Rust: a `rust-toolchain.toml` pins it and lists the targets, the Mac, the iPhone and its simulator in every architecture each builds for; `make bootstrap` installs rustup; the XCFramework is built from source, never committed; and CI caches Cargo's downloads and the XCFramework, so builds stay fast. Our crate is the only Rust of ours, and it passes rustfmt and clippy with warnings as errors in `make check`.
- The C interface passes plain values: stabilities, difficulties, intervals and parameters go across as numbers and structs, with no pointer kept across a call, and every exported function returns a status instead of letting a panic cross into Swift. cbindgen writes the header.
- This changes ADR 0005 and `CODING_STANDARDS.md`'s Layers, whose FichaCore imports only Foundation and the standard library's modules: FichaCore, still pure logic with time injected, also imports the FichaKit target that wraps fsrs-rs's C interface. What it calls to schedule is arithmetic alone, with no file, network or clock. `swift test` still runs without building the app, once the XCFramework is built.
- It keeps the app 100% local (ADR 0001): Cargo downloads crates at build time, as SwiftPM downloads packages, and nothing at run time.
- The tests check Ficha's use of fsrs-rs, not fsrs-rs itself, but a few keep fsrs-rs's own expected values, so an upgrade that changes them fails loudly.
- Standard practice: fsrs-rs at the version Anki ships; a Rust static library behind a C interface whose header cbindgen writes, as Rust's FFI documentation and cbindgen describe; an XCFramework of static libraries linked as a SwiftPM binary target, as Apple's and SwiftPM's documentation describe; and `rust-toolchain.toml`, as rustup documents.
- Our own: the wrapper crate and its few functions; which of Anki's rules stay in Swift; FichaCore importing the wrapper; building the XCFramework from source rather than committing it; upgrades of fsrs-rs as `risk:high` PRs; and the tests that keep fsrs-rs's expected values.
